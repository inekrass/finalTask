## Назначение и архитектура

My Tasks — одностраничный список дел с созданием, просмотром, редактированием, отметкой выполнения и удалением. Задачи сохраняются в PostgreSQL. Группы разделены идентификатором `runId`; в начальной группе `manual` создана обязательная запись «Итоговая работа 24.10.2026: inekrass».

Клиент написан на HTML, CSS и JavaScript без фреймворков (`public/`). Запросы `fetch` обрабатывает Express 5 (`src/server.js`), подключённый к PostgreSQL через `pg.Pool` (`src/db.js`). Сервер размещён на Vercel Hobby по HTTPS, база — в Neon Free. Версии: Node.js 24.x, PostgreSQL 18.

Все маршруты `/api/` требуют заголовок `Authorization: Bearer <token>`. Токен вводится в интерфейсе, хранится в памяти страницы и проверяется сервером; в исходный код не встроен. Сервер сам определяет автора, UUID, дату создания и исходный статус `done=false`. Запросы к БД параметризованы. API выдаёт актуальное состояние БД без локальных заглушек.

## Структура данных

Таблица создаётся файлом [`sql/schema.sql`](sql/schema.sql) и называется `public.tasks`. Физические имена столбцов отличаются от некоторых полей JSON:

| Поле API     | Столбец PostgreSQL | Тип                                  |
| ------------ | ------------------ | ------------------------------------ |
| `id`         | `id`               | `UUID PRIMARY KEY`                   |
| `ownerLogin` | `owner_login`      | `TEXT NOT NULL`                      |
| `title`      | `title`            | `VARCHAR(200) NOT NULL`              |
| `done`       | `done`             | `BOOLEAN NOT NULL DEFAULT FALSE`     |
| `runId`      | `run_id`           | `VARCHAR(64) NOT NULL`               |
| `createdAt`  | `created_at`       | `TIMESTAMPTZ NOT NULL DEFAULT NOW()` |

`createdAt` передаётся в UTC в формате ISO 8601. Название содержит 1–200 символов после обрезки пробелов, `runId` — 1–64 символа из латинских букв, цифр, `_` и `-`.

## Установка и запуск

```bash
git clone https://github.com/inekrass/finalTask.git
cd finalTask
npm ci
cp .env.example .env
```

Заполните `.env`: `DATABASE_URL`, `API_TOKEN`, `MOODLE_LOGIN`, `MOODLE_FULL_NAME` (необязательно `PORT=3000`). Создайте таблицу с правами владельца:

```bash
DB_URL=$(node -e 'require("dotenv").config({quiet:true}); process.stdout.write(process.env.DATABASE_URL)')
psql "$DB_URL" -f sql/schema.sql
npm start
```

Откройте `http://localhost:3000/`. На Vercel переменные задаются в панели проекта. `.env` и секреты не публикуются.

## HTTP API

| Метод  | Путь                       | Ответ                                         |
| ------ | -------------------------- | --------------------------------------------- |
| GET    | `/login/`                  | `200`, Moodle-логин, `text/plain`, без токена |
| GET    | `/api/author/`             | `200`, JSON с `login` и `fullName`            |
| POST   | `/api/tasks/`              | `201`, новая задача (`title`, `runId`)        |
| GET    | `/api/tasks/?runId=manual` | `200`, JSON-массив                            |
| GET    | `/api/tasks/:id/`          | `200` или `404`                               |
| PATCH  | `/api/tasks/:id/`          | `200`, изменение `title` и/или `done`         |
| DELETE | `/api/tasks/:id/`          | `204` без тела или `404`                      |

Невалидные данные возвращают `400`, отсутствие или ошибка токена — `401`, недоступность базы — `503`. Ошибки API оформлены как JSON с полем `error`.

## Анализ размещения БД

Сравнивались три варианта PostgreSQL. Neon выбран благодаря бессрочному бесплатному тарифу, TLS-подключению и возможности создать ограниченную SQL-роль для преподавателя. Это постоянный тариф с квотами, а не временный пробный период. Neon проверен практически: SQL-операции через `psql` и работа опубликованного приложения. Для альтернатив просмотрены официальные тарифы; отдельные базы там не создавались.

## Проверка преподавателем

Для проверки создана отдельная роль `todo_reviewer`: `SELECT`, `INSERT`, `UPDATE`, `DELETE` только на `tasks`, без административных прав. Подключение и CRUD проверены через `psql`. Реквизиты БД и API-токен передаются **личным сообщением в Moodle**, не публикуются.

Подключение через psql:

```bash
psql "host=<HOST> port=5432 dbname=neondb user=todo_reviewer sslmode=require" -W
```

Замените `<HOST>` адресом сервера из личного сообщения.
